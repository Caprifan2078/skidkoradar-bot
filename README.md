# 🔎 СкидкоРадар — Telegram-бот поиска скидок

**Версия кода: v0.9 · 11 ноября 2026**

Исходники уже **загружены в этот приватный репозиторий**. Повторно скачивать или загружать ZIP не нужно.

**Проверено:** GitHub Actions распаковал проверенный архив, запустил 67 из 67 локальных тестов и сохранил исходники. После импорта добавлен отдельный CI workflow `SkidkoRadar tests` для следующих изменений.

**Ещё НЕ готово:** бот не развёрнут на круглосуточном сервере; живые каталоги цен и остатков «Пятёрочки», «Магнита», «Перекрёстка» не подтверждены и по умолчанию не подключены. Программные тесты с имитациями данных не доказывают, что товар действительно есть на полке.

## Что находится в проекте

- `bot.py` — Telegram-бот и команды.
- `storage.py` — SQLite, хранение настроек, наблюдаемых товаров и истории.
- `core.py`, `deals.py`, `pricehunt.py`, `watchlist.py` — проверка скидок и уведомлений.
- `discovery.py` — отслеживание доступных публичных скидочных Telegram-каналов.
- `providers.py` — адаптеры **для отдельно подключаемых источников данных магазинов**, включая экспериментальный неофициальный MCP для «Пятёрочки».
- `diagnostics.py` и `tests/` — диагностика и тесты.
- `Dockerfile`, `railway.json` — подготовка к облачному запуску.

## Запуск без компьютера

1. Используй уже созданного бота из BotFather. **Никому не отправляй токен, не добавляй его в GitHub и в коммиты.**
2. Если решишь проводить тестовый запуск, с Android открой Railway или другой совместимый облачный Docker-хостинг и подключи **этот** репозиторий GitHub.
3. В *секретных переменных сервера* задай `TELEGRAM_BOT_TOKEN` из BotFather и `DATABASE_PATH=/app/data/deals.sqlite3`. Для постоянной работы базы подключи persistent volume к `/app/data` с правами на запись для пользователя контейнера.
4. В первом запуске без `ALLOWED_USER_IDS` бот безопасно закрыт для посторонних, но позволяет выполнить команду `/id`. Получи собственный числовой Telegram ID, добавь `ALLOWED_USER_IDS=твой_id` в переменные сервера и перезапусти сервис.
5. Проверь `/start`, `/sources`, `/scan`, `/status`, `/doctor`, `/coverage`. До подключения реальных источников `/doctor` должен честно показывать недоступные сети.

Не оплачивай хостинг только ради проверки реальных адресных остатков: сначала нужно подтвердить источник хотя бы для одной сети. GitHub Actions выполняет тесты, **но не запускает Telegram-бота 24/7**.

## Команды

| Команда | Назначение |
|---|---|
| `/start`, `/help`, `/id` | Старт, помощь и ID пользователя |
| `/sources`, `/watch @channel`, `/scan` | Мониторинг скидочных каналов |
| `/autochannels on`, `/alerts 70` | Поиск дополнительных каналов и порог заявленных скидок |
| `/hunt`, `/track кофе`, `/tracks` | Поиск снижения цен в **подключённых** каталогах |
| `/search кофе` | Поиск товара по сохранённым магазинам |
| `/watchdeal Магнит: кофе 199 ₽`, `/checkwatch` | Наблюдение за конкретным товаром по цене |
| `/status`, `/doctor`, `/coverage` | Диагностика источников и фактического охвата |
| `/stores`, `/chains` | Сохранённые магазины и сети |

## Источники цен и наличие — приоритет следующей разработки

Для «Пятёрочки» в `providers.py` предусмотрено экспериментальное подключение стороннего `pyaterochka-mcp-tool`, но оно требует отдельного запуска и проверки совместимости. Остальные сети предполагают доверенные JSON-источники. **Не стоит использовать обходы авторизации, капч или антибот-защит.** Только работающие источники с допустимыми условиями использования.

Статусы наличия различаются: «есть по данным источника», «нет по данным источника» и «неизвестно». В ответе должны быть источник и время проверки. Интернет-остаток не гарантирует товар на полке.

## Проверки

```bash
python -m unittest discover -s tests -q
```

Это 67 тестов логики на локальных и имитированных данных, а не независимая проверка наличия товаров в российских сетях.
